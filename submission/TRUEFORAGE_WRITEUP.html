2. Starting point

TrueForage was built as an original VS Code extension rather than a forked coding agent. The project is TypeScript/Node-based, MIT licensed, and packages an extension with Agent, Review, and Ask modes. Its public repository contains source, documentation, fixtures, and tests; generated recordings, credentials, dependencies, builds, and local workspaces are excluded.

3. Architecture on TrueForge

VS Code extension ⇄ TrueForge SDK ⇄ local TrueForge agent loop ⇄ configured model
                                     ↕
                     authenticated loopback MCP bridge ⇄ workspace files / diagnostics / commands

The extension never calls an LLM provider directly. Local TrueForge owns the session, model request, streaming turn lifecycle, tool registration, approval lifecycle, context compaction, and provider credentials. The extension exposes a short-lived bearer-token-protected MCP bridge for workspace tools, then renders plans, command output, diffs, and review state inside VS Code.

Agent mode can apply coherent changes and run requested verification. Review mode keeps each hunk visible for accept/reject and uses native VS Code diffs. Ask mode exposes only read-only tools. Cancellation discards unapplied proposals and terminates owned command processes.

4. How context is selected

Explicit editor selections are hard edit boundaries in Inline/Review work. For repository tasks, TrueForage discovers up to 2,000 paths, scans up to 240 eligible text files / 8 MB, and selects 60-line excerpts using lexical matches, paths, definitions, symbols, test proximity, and explicit file references. Evidence is UTF-8 budgeted to 24,000 bytes without splitting characters or emitting overlapping excerpts.

Private configuration, binary/large files, symbolic links, dependency folders, and paths escaping the workspace are excluded. The selected context and its reason remain visible in the panel so a reviewer can see why each file was considered.

5. Model setup

A model is configured in local TrueForge under Settings → Models; the extension then runs TrueForage: Choose Model, which performs a small real connectivity check before use. Provider credentials stay in TrueForge. The extension supports an optional TrueFoundry AI Gateway setup using the exact Gateway URL, model ID, and PAT/VAT from the Gateway Playground code snippet; its token is stored in VS Code SecretStorage rather than source control.

For resilience, trueforage.fallbackModels holds one or more exact configured TrueForge model names. Failed turns discard pending proposals before retrying or switching to the fallback, preventing a failed provider from silently changing the workspace.

7. Tools used

  • VS Code Extension API, TypeScript, Node.js 22, npm, and Git/GitHub.
  • TrueForge 0.183.1 and @truefoundry/trueforge-sdk 0.183.0 for the agent loop, model routing, sessions, and tool approvals.
  • Model Context Protocol (MCP) for authenticated workspace operations: file discovery/read, context search, proposed/revised edits, apply/review, diagnostics, planning, workspace status, and command execution.
  • Flask 3.1.3, pytest 8.4.2, and Click 8.2.1 in the prepared competition workspace.

8. Known limitations

  • Real inference depends on the configured provider’s access, quota, billing, model availability, and network state; a configured provider alone is not proof that generation succeeds.
  • The local TrueForge harness is designed for loopback/personal use. Workspace commands execute with the user’s permissions; this is not an operating-system sandbox.
  • TrueForage does not claim the pending Flask A/B/C tasks were completed until they are visibly performed by a live TrueForge-routed model and the scorecard has final timestamps.
